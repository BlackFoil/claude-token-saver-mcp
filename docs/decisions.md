## DS-002: キュー方式

| 項目 | 内容 |
|:---|:---|
| **日付** | 2026-02-15 |
| **提案者** | Architect |
| **決定** | Promise-based FIFO（同時実行1、最大キュー10件） |
| **理由** | ローカルLLMはGPU排他利用が前提のため、同時実行1に制限。外部依存なし（Redis等不要）でシンプルに実装 |

### パラメータ

- `maxQueueLength`: 10
- `maxRequestSizeBytes`: 200 KB
- `queueTimeoutMs`: 30,000 ms
- オプション: レートリミッター（RPM制限）

## DS-008: 動的モデルセレクター — セッション固定方式

| 項目 | 内容 |
|:---|:---|
| **日付** | 2026-02-19 |
| **提案者** | PM / ユーザー |
| **レビュー** | Architect, UX Researcher, Governance |
| **決定** | Agent Team起動時にCLAUDE.mdのロール定義からLLM用途を読み取り、PCスペックに応じた最適モデルを推奨。ユーザー承認後、セッション固定で使用する |

### 背景

マルチエージェントチーム起動時に、コーディング用にはコーディング特化LLM、日本語タスクには日本語特化LLMを使い分けたいが、リクエストごとのモデル切替はボトルネックとなる。

### 検討した方式

| 方式 | 概要 | 採否 |
|:---|:---|:---:|
| A: セッション固定 | 起動時にモデル選択→セッション中固定 | **採用** |
| B: リクエスト毎切替 | ツール呼び出しごとにモデル切替 | 不採用 |

### 不採用理由（方式B）

Architect調査結果:
- Ollamaモデル切替コスト: **18〜35秒** (7B→32B)
- Agent Team全体のボトルネック化が確実
- MCP stdio transportでは起動時の対話的質問も不可能

### 採用方式の詳細

1. CLAUDE.mdの役割テーブルに `LLM用途` 列を追加
2. Claude Code (PM) が起動時にCLAUDE.mdを解析
3. `recommend_model` MCPツールで用途×Tier→最適モデルを照会
4. ユーザー承認後、`preload_model` でメモリ常駐 (`keep_alive: -1`)
5. 各エージェントは `offload_work(model="xxx")` で指定モデルを使用

### VRAM同時ロード制約

| PC RAM | 同時ロード可能 | 推奨 |
|:---|:---:|:---|
| < 16GB | 1モデル | 兼用モデル1つ |
| 16-48GB | 1-2モデル | coding + 汎用 |
| > 48GB | 2-3モデル | coding + japanese + 汎用 |

### ガバナンス承認条件

- 「推奨」に留め「自動選択」は避ける（特許リスク回避）
- ユーザー承認フローを必須化
- ライセンス情報を推奨時に常に表示
- Apache 2.0 / MIT モデルをデフォルト推奨
- Codestral (MNPL) はブロックリスト初期設定

### 参考: 特許リスク評価

| カテゴリ | リスク |
|:---|:---:|
| 特許侵害 | 低〜中 (Dropbox WO2025159854A1が関連するが技術的差異大) |
| ライセンス | 低 (推奨のみで再配布しない) |
| MCP仕様 | 低 (前例あり) |

## DS-009: PriorityQueue採用

| 項目 | 内容 |
|:---|:---|
| **日付** | 2026-03-16 |
| **決定** | FIFOQueueを維持しつつ、PriorityQueueを新規追加 |
